# Release 0.2.0 Design

## Goal

Prepare the accumulated lease hardening, watcher, CI, and adapter refactor
for a coordinated `0.2.0` Cargo and npm release.

## Design

Use `0.2.0` consistently in `Cargo.toml` and `package.json`, since the branch
adds a user-visible watcher command and changes persisted lease-state behavior
from an unversioned array to a versioned v2 envelope. Add a root
`CHANGELOG.md` entry describing the user-visible features, compatibility
warning for older binaries, and verification status.

Update `docs/RELEASING.md` so its checklist and tag examples target `v0.2.0`
and explicitly verify that Cargo, npm, and the release tag use the same
version. Keep publishing and pushing as separate manual steps; this work
prepares and validates the release but does not publish credentials or push
automatically.

## Alternatives Rejected

- Keeping `0.1.0` would make a second release indistinguishable from the
  existing tag and understate the new CLI/state behavior.
- Automating the tag, push, or registry publication in this change would make
  a local preparation step destructive and require credentials/network state.
- A full historical changelog rewrite is unnecessary; add a focused `0.2.0`
  entry and preserve existing release history if present.

## Verification

- Search tracked documentation and manifests for stale release references.
- Run formatting, Clippy, all tests, Cargo package/publish dry-run, and npm
  pack dry-run.
- Confirm generated package contents do not include build artifacts or secrets.
